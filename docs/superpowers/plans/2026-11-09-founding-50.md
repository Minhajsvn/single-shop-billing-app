# Founding 50 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The first 50 shops to pay get Pro features and limits for 12 months at the Starter price, shown in Settings, the admin console and the public site.

**Architecture:** A singleton `founding_offer` row and a `founding_members` table. `apply_billing_event` claims a seat (under a row lock on the singleton) when an applied event leaves a shop `active` on `starter`, and ends it on `subscription_deleted`. `entitlements_internal()` swaps in the `pro` catalog row for features and limits while a founder row is active and no grant is in force, and returns a new `founder` key.

**Tech Stack:** Postgres (Supabase, plpgsql), Next.js 16 App Router, TypeScript, zod, `node --test`, `postgres` npm client.

**Spec:** `docs/superpowers/specs/2026-11-09-founding-50-design.md`

## Global Constraints

- Seat cap 50, period 12 months: both live in `founding_offer` (`seat_cap`, `months`), never hard-coded elsewhere in SQL.
- One `founding_members` row per business, ever. A seat is "taken" unless `end_reason = 'revoked'`.
- Claims only after an `applied` event of kind `checkout_completed | invoice_paid | subscription_changed` that leaves `status = 'active'` and `plan_id = 'starter'`.
- `apply_billing_event` return values are unchanged. Its body is copied from `202610310043_razorpay_billing.sql` with only the additions in Task 1.
- `entitlements_internal` body is copied from `202610290040_plan_grants.sql` with only the changes in Task 2. `planId` stays the subscription's; a grant in force hides the founder.
- New tables: RLS on, no policies, `revoke all` from `public, anon, authenticated`, `select` to `service_role`.
- Copy (exact):
  - Settings: `Founding member #N: Pro features at the Starter price until <date>.` plus, within 30 days of the end, ` After that, Starter limits apply.`
  - Public: `Founding 50: the first 50 shops to subscribe get Pro features for 12 months at the Starter price.`
  - Admin refusal `not_a_founder`: `This shop is not a founding member.`
- Dates in UI use the existing Dubai helpers (`dubaiDate`, `adminDateTime`).
- Local only: every DB command targets local Supabase (`postgresql://postgres:postgres@127.0.0.1:54322/postgres`, API `http://127.0.0.1:54321`). The main checkout's `.env.local` points at **production**; the worktree gets its own `.env.local` (Task 0). No production migration without the owner's explicit go-ahead.

## Review Focus

1. A Razorpay redelivery of the claiming `invoice_paid` (`duplicate`) must not claim twice or error. Test in Task 1.
2. A founder who goes `past_due` keeps the benefit through grace; only `subscription_deleted` ends it. Test in Task 1.
3. Cached entitlements written before this change (no `founder` key) must still parse. Test in Task 4.
4. `founding_offer_open()` failing or the network being down must hide the public offer text, not break the home page or signup. Test in Task 6.
5. A shop whose founder period has ended must show no founder line in Settings and "ended" (not active) in admin. Tests in Tasks 4 and 5.
